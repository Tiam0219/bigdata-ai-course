# concept-learning —— 概念学习资料生成 Skill

## 一、适用场景

当你需要围绕一个**不熟悉的概念**系统性地学习并产出一份可复用的学习资料时使用本 Skill，典型场景：

- 课程作业：老师给出若干新概念，要求每人写学习笔记并提交仓库；
- 技术调研：团队引入新工具/新范式，需要快速产出入门材料；
- 知识沉淀：把"每次都要重新给人解释一遍"的概念整理成一份标准文档；
- 自学扫盲：遇到新名词（如 Agent、上下文、RAG、MCP），想搞懂它到底是什么、怎么用、边界在哪。

不适用：需要动手实验验证的课题（应走实验/代码类 Skill）、纯观点类写作（应走写作类 Skill）。

## 二、输入信息

| 输入项 | 必填 | 说明 |
|--------|------|------|
| 学习主题 | 是 | 一个或多个概念名称，如 "Agent"、"大模型的上下文"、"Skill" |
| 背景说明 | 建议 | 为什么学这个概念、学习者的基础水平，用于调整解释深度 |
| 输出路径 | 建议 | 学习资料存放目录；缺省为仓库内 `learning-materials/` |
| 特殊要求 | 可选 | 字数、语言、图表数量等 |

## 三、生成步骤

对每个概念依次执行以下 8 步：

1. **检索资料**：通过网络搜索 + 抓取**白名单来源**（见第五节），收集 2~4 个独立来源。禁止把黑名单来源作为依据。
2. **交叉验证**：同一关键结论至少要有两个来源相互印证；来源之间有冲突时，在资料中如实标注分歧，而不是擅自取舍。
3. **形成个人解释**：合上资料，用自己的话（打比方、举例子）写 2~4 段解释——这是"费曼式检验"，写不出来说明还没真正理解，回到第 1 步。
4. **结构化撰写**：严格按第四节的输出结构组织内容，重点写"核心机制/组成"和"易混淆问题与使用边界"两节——这两节最能区分"背定义"和"真理解"。
5. **绘制机制图**：为"核心机制/组成"一节配至少 1 张 Mermaid 图（GitHub 可渲染的 flowchart/sequence 等标准语法），图中元素必须与正文一一对应，不引入正文没有的组件。
6. **编制自测题**：围绕第 4 节的易混淆点出 3~5 道题（选择/判断/简答混合），附答案与解析；题目必须能"考出"易混淆点，不出背诵式送分题。
7. **补充可核查来源**：为每份资料附上来源清单（标题、作者/机构、发布时间、URL、验证日期、一句话说明该来源提供了什么）。所有 URL 必须实际访问验证过，失效链接不得写入。
8. **自检与审查**：执行第六节的自检清单，并按第七节完成双重自我审查，全部通过后才算完成。

## 四、输出结构

每个概念生成一个 Markdown 文件，保存到输出目录，文件名用概念英文小写或拼音命名（如 `agent.md`、`llm-context.md`）：

```markdown
# 概念名称

> 一句话定义（一句加粗的话，不复制原文，自己概括）

## 1. 我的个人解释
（用大白话 + 比喻 + 例子，2~4 段）

## 2. 核心机制 / 组成
（拆解该概念由哪几部分构成、各部分如何协作；可用表格或列表）
（必须配至少 1 张 Mermaid 机制图，与正文内容一一对应）

## 3. 具体应用场景
（至少 1 个具体、可落地的场景，说明"谁在什么情况下用它解决什么问题"）

## 4. 易混淆问题与使用边界
（它不是什么；它和哪些相近概念的区别；什么情况下不该用它）

## 5. 自测题
（3~5 道，选择/判断/简答混合，题目须覆盖第 4 节的易混淆点；
答案与解析集中放在题目之后的"答案与解析"小节）

## 6. 资料来源
（可核查的一手来源清单：标题、作者/机构、时间、URL、验证日期、来源提供的内容）

## 7. 自检报告
（逐项对照 Skill 自检清单，给出 ✅/❌ 及证据说明）
```

多概念作业需额外产出 `concept-relationship.md`，用文字 + 表格 + **1 张总览 Mermaid 图 + 每个重点关系 1 张专题图**说明概念间的关系，一图只说一件事。

## 五、资料来源要求（白名单 / 黑名单制度）

**每份资料至少 2 个、总数 2~4 个相互独立的一手来源，且必须全部来自白名单：**

| 类别 | ✅ 白名单（可作为引用来源） | 示例 |
|------|------------------------------|------|
| 学术论文 | arXiv 预印本（注明版本状态）、顶会/顶刊论文（NeurIPS、ICLR、ACL、CVPR 等） | Attention Is All You Need（arXiv:1706.03762）、ReAct（ICLR 2023） |
| 官方一手文档 | 厂商/组织的官方文档、官方工程博客、官方标准文档 | Anthropic Engineering、Claude Code Docs、W3C/ISO 标准 |
| 知名研究者一手技术博客 | 由概念领域的一线研究者本人撰写、被广泛引用的长文（须注明作者身份） | Lilian Weng (Lil'Log)、Simon Willison |
| 开放标准/规范官网 | 标准本身的官方站点 | agentskills.io |

| ❌ 黑名单（不得作为引用来源） | 说明 |
|------------------------------|------|
| 论坛帖子、问答区（知乎回答、Stack Overflow、贴吧、V2EX） | 讨论质量参差，结论未经同行评议或官方审核 |
| 内容农场/转载站（CSDN 转载、微信公众号转载、掘金/博客园抄录） | 二手转述，常有错漏且无法溯源 |
| 营销软文、新闻稿式"评测" | 带商业目的，非技术一手来源 |
| AI 生成的汇总页（需人工判定） | 无法保证事实正确性 |

补充规则：

- 黑名单来源**只可用作检索线索**（顺着它找到原始论文/官方文档），绝不出现在来源表中；
- 每条来源注明：标题、作者或机构、发布时间、完整 URL、**验证日期**、该来源为本文提供了什么内容；
- 所有 URL 在写入前必须实际访问验证可达；
- arXiv 预印本须注明是否已被会议/期刊录用；
- 引用他人原文的地方要标注来源，其余内容应是消化后的再表述，不整段照抄。

## 六、自检要求

产出后逐项检查，任何一项不通过则返工：

- [ ] **通用性**：换一个新的概念（如 "RAG"），本 Skill 的步骤和输出结构依然适用，而不是只为某个概念写的一次性提示词；
- [ ] **个人解释**：解释中没有直接照抄任何来源的原文句子；
- [ ] **机制完整**：核心机制/组成覆盖了定义中提到的每个关键要素；
- [ ] **图示正确**：Mermaid 图语法正确（GitHub 可渲染），图中元素与正文一一对应，无正文没有的组件；
- [ ] **场景具体**：应用场景有时间、人物、动作、结果，不是空泛的"广泛应用于各行各业"；
- [ ] **边界清晰**：易混淆问题至少指出 1 个相近概念并说明区别；
- [ ] **自测题有效**：3~5 道题覆盖了全部易混淆点，题干不直接泄露答案，附答案与解析；
- [ ] **来源合规**：每条来源均属白名单类别、URL 验证可达（注明验证日期）、确实支撑文中相应论述；
- [ ] **自检报告完整**：第七节逐项对照本清单给出 ✅/❌ 及证据；
- [ ] **安全合规**：内容不含 API Key、密码、个人隐私等敏感信息。

## 七、自我审查（双重审查）

自检清单之外，完成以下两层审查并留痕：

**第一层：内容审查（对产出物）**

- 逐条打开来源链接，核对文中每个关键论断确实被该来源支撑（防止"引用了但内容对不上"）；
- 核对 Mermaid 图与正文、表格三者相互一致；
- 核对自测题答案与正文内容一致，不存在答案与资料矛盾的题目；
- 检查全文无敏感信息。

**第二层：功能审查（对 Skill 本身，验证可用性）**

- **通用性实测**：任选一个本次任务之外的新概念（如 RAG、MCP），**实际走一遍**本 Skill 的 8 步流程，确认每一步都能执行、输出结构六/七节都能填上，产出物通过自检清单——实测通过才能声明 Skill 可用；
- 实测记录（选用概念、执行日期、各步骤通过情况、发现的问题及修正）写入 README 的"人工核查"章节或单独的实测记录文件，作为可审查的证据；
- 若实测发现流程缺陷（某一步执行不了、某节填不出来），**先修正 SKILL.md 再重新实测**，直至通过。
